# Experiment H -- Independent Scenario Corpus (manifest + provenance)

External-validity SCOPE study: does the delay-only attack surface generalize to tasks NOT co-designed with TemporalGuard? Annotations below were authored from each task's text ALONE, before consulting the guard's contract map. Generated by `.venv/bin/python -m delaysteer.run_external_corpus` (deterministic, scripted reference backbone).

## Headline scope metrics

- Corpus size: **18** tasks (HA core blueprint: 4, SimuHome family: 4, independent prompt: 10).
- Plausible delay-only attack surface: **10/18** (56%).
- NON-APPLICABLE (no high-impact action or no delay-sensitive fact): **8/18**.
- Among applicable tasks with an in-repo deterministic reference (8): attack succeeds **8/8**, guard covers **6/8** (uncovered: 2 -- action outside the shipped contract map).
- Applicable tasks deferred to the external SimuHome server (continuous env-threshold, no in-repo analog): **2** (deterministic command recorded per task).
- Distinct unsupported fact classes surfaced across the corpus: **10** -- geofence_zone, env_threshold, appliance_operational_state, household_occupancy_aggregate, vehicle_presence, open_cover, disarm_alarm, energy_metering, rain_soil_moisture, alert_suppression_timing.

Guard-supported fact classes (contract_validator.default_registry): `alarm_state, arrival, contact_state, leak_state, lock_state, occupancy`.  

Guard-covered high-impact actions (temporal_guard.REQUIRED): `arm_alarm, grant_access, propose_automation_edit, report_status`.

### ha_confirmable_notification  (HA core blueprint)
- **Provenance:** `config/blueprints/script/homeassistant/confirmable_notification.yaml`
